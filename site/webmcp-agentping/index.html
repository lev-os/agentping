The Problem

AI agents are blind on the open web

Every agent framework hits the same wall: the web was built for humans with eyeballs, not machines with token budgets.

2,000 tokens per screenshot

Agents waste context on pixels

Every screenshot eats 2,000+ tokens of context window. A 5-step workflow burns 10,000 tokens just looking at pages — before the agent even reasons about them. That is money and latency set on fire.

Cloudflare blocks headless browsers

The cookie extraction ceremony

Headless Chrome gets blocked instantly. So you export cookies, inject them into Playwright, pray the session holds, and restart when it doesn't. A five-minute task becomes a thirty-minute ritual.

DOM changes break everything

Selectors rot overnight

CSS selectors are a bet against every deploy. One class rename, one React key change, and your entire automation is dead. Agents built on selectors are inherently fragile.

# slack.webmcp.yaml
name: slack
version: 1.0.0
match: "*.slack.com/*"

tools:
  send_message:
    description: "Send a message to the current channel"
    params:
      text: { type: string, required: true }
    action:
      selector: "[data-qa='message_input']"
      steps: [focus, clear, type, submit]

  read_messages:
    description: "Read recent messages from the current channel"
    params:
      limit: { type: number, default: 10 }
    returns: Message[]

How It Works

Three steps. Fifty tokens.

1

Extension injects the polyfill

The AgentPing extension injects the WebMCP shim into every page you visit, exposing navigator.modelContext as a structured API surface.

// Extension content script navigator.modelContext = new WebMCPShim(); shim.loadTools("chatgpt.webmcp.yaml");
2

Tool definitions load from registry

Matching .webmcp.yaml definitions are loaded from the community registry (or auto-generated on the fly via agentic crawling).

tools: - name: send_message params: { text: string } - name: switch_model params: { model: string }
3

Agent calls structured tools

Your agent calls semantic tools directly. No vision model. No coordinate math. Just clean function calls.

// 50 tokens. Instant. await agent.callTool("send_message", { text: "Deploy approved. Ship it." }); // Returns structured data, not pixels const msgs = await agent.callTool("read_messages", { limit: 5 });

The Marketplace

Like Greasemonkey scripts, but for AI agents

A growing registry of community-contributed tool definitions. One YAML file per site. Version-controlled. Fork-friendly.

Community-Contributed

Open contribution model

Anyone can submit a .webmcp.yaml for any site. Review, fork, and improve — just like userscripts, but with schema validation and semantic versioning.

Auto-Generated

Agentic crawling

No YAML for a site yet? The extension can auto-generate tool definitions by crawling the page structure. AI writes the tool schema so you don't have to.

Version-Controlled

Pinned and reproducible

Lock to a specific version. Roll back when sites change. CI-testable definitions ensure your agent workflows stay green across deploys.

Native Handoff

Graceful deferral to native WebMCP

When browsers ship native navigator.modelContext, the shim detects it and steps aside. Your tool definitions keep working. Zero migration cost.
