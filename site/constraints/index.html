Constraint Engineering

The Seal That
Only Tightens

How two axioms and a ratchet model make agent chaos impossible

Most agent frameworks let agents do whatever they want and pray for alignment.
Leviathan starts from the opposite premise: constraint is the product.

The Problem

Why Unconstrained Agents Are Dangerous

Give an LLM a tool and watch what happens. It calls everything. It retries forever. It "fixes" your config while you sleep. The zoo has no fences.

Silent Mutation

Agents change state without receipts

An agent writes to disk, mutates a database row, pushes a commit. No audit trail. No proof of what changed or why. When something breaks at 3am, you have no causal chain to follow. Just a diff and a prayer.

Ambient Authority

Agents assume permissions they were never granted

The agent has a shell. The shell has your SSH keys. Congratulations, your staging server is now the agent's playground. Most frameworks treat permissions as an afterthought. The blast radius is your entire environment.

Infinite Loops

No budget bounds, no termination guarantee

The agent spins. It calls itself. It burns tokens at $0.03 per thousand while you're at lunch. Without explicit finitude constraints, every agent is one hallucination away from an infinite bill.

You don't have an AI safety problem. You have a constraints problem.

The Foundation

Two Rules. Everything Derives.

Leviathan's entire constraint model rests on two axioms. They are not guidelines. They are not best practices. They are the physics of the system. Violate either one and the runtime treats it as FATAL.

C1 — Finitude

"All resources are finite. Time, tokens, context, memory, compute, attention."

Implication: Every operation must be bounded. No infinite loops. No unbounded growth. Every agent call has a token budget. Every loop has an iteration cap. Every session has a wall-clock timeout. If it can grow, it has a ceiling.
violation: FATAL
C2 — Non-Commutation

"Order matters. A then B ≠ B then A. History is irreversible."

Implication: Append-only event logs. Immutable receipts. No silent mutation. Deterministic replay. If you wrote it, it's written. If you need to undo it, you write a compensation event. The log never lies.
violation: FATAL

That's it. Two axioms. C1 says things end. C2 says order is permanent. Everything else in the system -- the governance rules, the gate taxonomy, the tick cycle, the graph primitives -- derives from these two.

C1 + C2 are the irreducible root. C3 through C5 are governance rules, derived from them but not yet formally proven. They carry status: assumed and violation: ERROR until someone writes the proof.

C3 — Nominalized Reality

Only validated canonical YAML executes

No semantic smuggling. If it didn't pass schema validation, it doesn't run. The runtime interprets declarations, not intentions.

Entailed by finitude (finite encoding) + non-commutation (order-dependent naming)
C4 — Ratchet Convergence

State transitions converge toward attractor basins

Rollback requires explicit compensation. Append-only by default. The system moves forward or it explains why it can't.

Emergent from finitude (bounded state space) + non-commutation (path-dependent selection)
C5 — Locality

Every step has explicit scope

No omniscience. No ambient authority. An agent knows only what its context window contains and can only touch what its guard permits.

Entailed by finitude (finite probes) + non-commutation (no state teleportation)

The Ratchet

Constraints That Only Tighten

A ratchet is a mechanical device that permits motion in one direction only. In Leviathan, the constraint model works the same way. Permissions narrow. They never widen implicitly. 

gate: admission_control
mode: fail_closed

policy:
  - schema_valid: required
  - term_fence: enforced
  - capability_check: deny_unknown

on_fail: deny

# no inference. no repair.
# no silent failures.

Fail Closed by Default

If the kernel can't evaluate a policy, the action is denied. Not deferred. Not logged-and-continued. Denied.

Schema validation is required, not optional. If the payload doesn't match the contract, the gate rejects it before any handler sees it.

Term fences enforce vocabulary. An agent can't invent new event types or smuggle semantics through freeform strings. The vernacular is fixed.

Capability checks default to deny_unknown. If a capability isn't explicitly granted, it doesn't exist. There is no "try it and see."

The ratchet metaphor goes deeper than access control. State transitions converge toward attractor basins. An entity moves from ephemeral to captured to crystallized to completed. Each transition is a one-way door.

Rollback is not deletion. Rollback is a compensation event -- a new entry in the append-only log that explicitly reverses a prior decision. The original record stays. The causal chain is preserved. C2 demands it.

This is why unconstrained agents are structurally impossible in Leviathan. The system doesn't trust them. It doesn't need to. Every mutation goes through a gate. Every gate enforces a contract. Every contract is a ratchet.

Validation Gates

Invariants at Every Boundary

Gates are evaluators. They sit between a proposal and its application. The severity model tells you how hard the wall is.

Enforced

Automated check exists and runs

Violations block. The CI won't pass. The runtime won't proceed. This is a wall, not a warning.

Declared

Manual review only

The rule exists. The automated checker doesn't yet. Humans enforce this gate during review. Promotion to enforced is planned.

Aspirational

Target state

Not yet enforced or fully implemented. The system knows this invariant should hold. It's queued, not forgotten.

Gate Taxonomy

Gate Rule Status
poly_compliance Adapter pattern, independently startable subsystems, LevEvent schema declared
no_poly_handlers Poly has zero business logic handlers. All handlers live in owning modules. enforced
no_commands_dir No src/commands/ directories. Use src/handlers/. aspirational
no_export_star No export * re-exporting other packages. Each package owns its API surface. aspirational
fractal_naming handlers/, surfaces/, generated/, contracts/ aspirational
config_lint Every plugin must have a config.yaml. Filesystem IS the registry. enforced
dna_authoring_canon dna/authoring/ root exists, parses, each canon file carries a validation block. enforced

Gates compose. The DNA canon (dna/gates.yaml) defines the root taxonomy. Project-level overlays (.lev/validation-gates.yaml) extend them for specific repositories. Runtime contracts add execution-time gates for orchestration, exec, and SDLC flows.

Every gate evaluates five dimensions: scope (is this within boundary?), safety (secrets, destructive actions?), feasibility (tools available? permissions held?), standards (rules, formatting, invariants?), and progress (did the last tick measurably advance?).

The Tick Cycle

Universal Execution Substrate

Every message is a Tick. Every mutation flows through the same seven-phase cycle. The gate sits between PROPOSE and APPLY. No mutation without a gate.

Ingest
→
Observe
→
Propose
→
Gate
→
Apply
→
Update
→
Emit

INGEST receives the input. A user prompt. An event from another system. A webhook. A file change. Doesn't matter what -- the tick cycle normalizes it.

OBSERVE reads current graph state. What entities exist? What claims are active? What's the context window? This is read-only. No side effects.

PROPOSE generates a candidate mutation. A proposal is like a pull request against the graph. It contains a list of operations and their expected effects. It is not applied. It is not committed. It is a candidate.

GATE is the wall. The proposal passes through every applicable gate. Scope check. Safety check. Feasibility check. Standards check. Progress check. If any gate rejects, the proposal is denied. No negotiation.

APPLY executes the accepted proposal. Graph state mutates. Side effects fire. This is the only phase where state changes. Everything before is planning. Everything after is observation.

UPDATE refreshes materialized views and projections. Dashboards update. Caches invalidate. Downstream consumers get notified.

EMIT publishes the result as a LevEvent. Other systems can subscribe. Other agents can react. The cycle is complete. The next tick begins.

Graph Primitives

The Vocabulary of Constraint

Eight primitive types form the graph's ontology. Everything in the system is one of these. No exceptions. No escape hatches.

entity

A node in the graph. Everything is an entity. Files, agents, configs, claims -- all entities.

claim

An atomic assertion about an entity. Has a truth_state: proposed, accepted, contested, refuted, superseded.

evidence

Proof for a claim. Append-only. Kinds: observation, log, measurement, attestation, derived.

proposal

A candidate graph mutation. Like a pull request. Operations list requiring gates. Status: pending, amended, accepted, rejected.

gate

Evaluator that allows, amends, or rejects proposals by enforcing contracts and policies. The wall between intent and action.

view

Materialized projection over graph state. Lossy by design, scoped and time-bounded. Dashboards, reports, prompts.

tick

One cycle: INGEST, OBSERVE, PROPOSE, GATE, APPLY, UPDATE, EMIT. The heartbeat of execution.

intent

Cascading behavior spec. Governs child entities via governs links. Hard constraints additive, steering overridable.

Notice the triad at the center: proposal, gate, and receipt. A proposal is a candidate mutation. A gate evaluates it. A receipt is the immutable proof that work was completed. This triad is the enforcement mechanism for C2 -- every mutation leaves a permanent, ordered trace.

The receipt primitive bundles eval results, effect results, content hash, and provenance. It is the finality boundary. Once a receipt exists, the work is done. The record is permanent. The history is closed.
